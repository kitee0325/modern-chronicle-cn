# Scroll Chronicle：晨间验收说明

## 已完成的可验收范围

- 21 组素材已按顺序接入一条 GSAP 主时间轴，并由一个顶层 `ScrollTrigger` 控制。
- 正向、反向、滚动条跳转都回放同一条时间轴；没有 scene snap、wheel 劫持或独立补动画。
- 背景、全局小船、前景按固定层级渲染。列车内会提前把下一段窗外背景放到车厢前景之后。
- 全篇只有一个小船节点；航行由 scroll 控制，内层晃动是唯一的独立循环。最终小船从右侧驶出。
- 横向、同构渐变、下钻和上浮四类转场均已实现为可逆 tween。
- 窄屏为居中的 16:9 电影画幅并使用纯黑上下遮幅；宽屏保持素材高度并展示更多横向内容。
- 运行时仅为当前 scene 前后一定范围设置图片 `src`，远端素材不会全部同时解码。
- `prefers-reduced-motion` 会停止船体循环，并把门户缩放降级为滚动控制的淡化。

## 本轮实现采用的临时最佳实践

### 1. 车窗门户几何

当前导出资产没有提供每个窗口的独立 mask、`windowRect` 或遮挡物坐标。因此下钻/上浮采用统一的中心门户：外景从中央裁切区展开，车厢层围绕安全舞台中心缩放。它完全跟随 scroll 且可逆，但并不声称已经逐窗像素对齐。

这正是本轮留给人工验收的主要部分。若要精确到每一扇窗，需要补充每个列车 scene 的窗口矩形或 mask 资产；届时只替换 scene manifest 中的门户参数，不需要改时间轴架构。

### 2. 文本和图表

现有 PNG 已把多数文字、图表、人物与纹理烘焙在同一个 raster 中，仓库没有对应的 DOM 文案、图表数据或独立图层。因此本轮按“整块 raster 内容”处理：内容随摄影机进入安全区、在画幅外被裁切，并在反向滚动时重新进入。

这满足滚动可逆与重复显隐，但无法实现“坐标轴 → 数据 → 注释”的语义级分段动画。若该项是最终硬验收标准，需要设计侧补交分层文本/图表资产或结构化数据。

### 3. 最终 scene

实现已把 `public/assets/scenes/Scene_21` 作为确定的最终长卷使用，并在其末段让船驶出。Figma 名称仍标记为 `Scene_09_01（待定）`，只影响命名确认，不影响当前素材顺序和运行结果。

### 4. 超长图性能

当前通过邻近 scene 解码和取消全量 `will-change` 控制内存及合成开销。`Scene_21` 的原图宽度为 15734px，桌面 Chrome 验收可正常渲染，但低端移动设备仍存在峰值内存风险。

若目标设备包含低内存 WebView，下一步应在构建期把超长图切成不超过 4096px 的重叠瓦片，并把 `sceneAssets` 扩展成 tile manifest。本轮未擅自生成瓦片，以免改变静态素材交付方式。
