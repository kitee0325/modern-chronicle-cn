# 页面启动 Loading 场景设计

## 目标

在应用内容出现前提供一段简洁、克制、与现有 Figma 场景稿一致的启动动画。当前使用模拟加载进度，后续可无缝替换为图片、音频等真实资源的加载进度。

全站文字统一使用用户提供的“方正大标宋简体”本地字体，并保留系统中文字体作为加载失败时的兜底。

## 视觉方向

- 使用设计稿中的低饱和现代城市叙事：米白底色、深棕轮廓、灰蓝建筑、墨绿进度强调和少量浅粉点缀。
- 页面保留大面积留白，不使用卡片、玻璃效果、霓虹、复杂纹理或高频装饰。
- 中央主体是一条横向城市天际线，底部轨道同时承担进度基线。
- 下方仅保留百分比和“城市记忆正在展开”状态文案。
- 桌面端保持宽阔横向构图。轨道两端预留不小于半个列车宽度的安全区，使列车在 0% 和 100% 都完整位于视口内。
- 600px 以下进入窄屏布局：主体宽度为视口减 32px，先隐藏最左和最右两栋点缀建筑，再整体等比缩小；状态文案保持单行，百分比固定在轨道右下方。320px 宽度下不允许文字重叠或横向滚动。

## 动效叙事

加载进度从 0 到 100 平滑推进，列车本身就是进度指示器：

1. 页面进入时，米白背景先显现，轨道线从左向右展开。
2. 列车沿轨道从左向右行驶，其车头水平位置直接映射当前加载百分比；0% 和 100% 对应轨道安全区的起点与终点。
3. 每栋建筑拥有轨道上的固定锚点。仅当列车尾部越过该锚点时，建筑进入出现队列；触发阈值由建筑锚点、轨道有效宽度和列车宽度共同换算，不能只用视觉上近似的百分比。
4. 建筑从轨道下方依次“冒出”：先上移并淡入，再以很小幅度回落稳定。若低帧率、后台恢复或未来真实进度跳跃导致一次跨过多个锚点，新触发的建筑按稳定索引进入独立出现队列，以 90ms 间隔依次播放；该队列只调度出现事件，不维护或修改加载进度。
5. 建筑出现后保持静止，不添加持续呼吸、漂浮或弹跳。
6. 百分比随进度更新；状态文案保持稳定，避免与主体争抢注意力。
7. 90–100% 阶段共 0.8 秒，其中最后 300ms 使用缓出曲线减速并同步到达 100%。进度到达 100% 后先等待建筑出现队列清空、最后一栋完成稳定，再让完整城市轮廓静止停留 350ms。Loading 随后用 420ms 淡出并轻微上移，主页面同步淡入。

动画使用缓出曲线，避免机械匀速和夸张弹簧。开启 `prefers-reduced-motion` 时，轨道和建筑直接显示，列车固定在轨道起点且不随进度移动，只保留百分比表达进度；到达 100% 时列车无过渡地切换到终点。停留缩短为 100ms，退场在 150ms 内只改变透明度；不使用 transform、弹性或持续动画。

## 组件与职责

### `AppLoading`

- 接收 `progress`、`phase` 和可选状态文案。
- 负责覆盖层、百分比、退场状态与无障碍属性。
- 使用 `role="progressbar"` 和 `aria-label="页面加载进度"`，提供 `aria-valuemin`、`aria-valuemax` 和 `aria-valuenow`。视觉位置可连续更新，但 `aria-valuenow` 只按整数且最多每秒更新 4 次，避免读屏重复播报。

### `LoadingCity`

- 渲染轨道、列车和简化城市轮廓。
- 每栋建筑声明自己的出现阈值；根据当前进度切换可见状态。
- 列车位置由进度派生，不维护第二套动画进度，避免视觉与数字不同步。
- 建筑出现队列只记录首次跨过的新锚点；严格按建筑索引调度，组件卸载时清理未执行事件。
- 通过 `onRevealQueueIdle` 通知协调层队列已清空且最后一栋稳定；正常完成时不得在该通知前开始完整画面的停留计时。异常降级直接完成剩余建筑并清空队列，卸载则取消队列。

### `useSimulatedProgress`

- 当前阶段基于 `requestAnimationFrame` 的 elapsed time 生成平滑模拟进度，目标总时长 3.6 秒（允许浏览器调度产生约 ±150ms 差异）。
- 0–55% 用 1.3 秒、55–90% 用 1.5 秒、90–100% 用最后 0.8 秒缓出完成；数值始终 clamp 在 0–100、单调不回退，并且只完成一次。视觉使用浮点值，展示和 ARIA 使用整数值。
- 暴露与真实资源加载一致的 0–100 数值边界；后续替换数据来源时，UI 组件无需修改。

### 全局字体

- 将提供的 TTF 文件纳入项目字体资源，通过 `@font-face` 声明。
- 在 `:root`、表单控件和按钮统一使用该字体。
- 设置 `font-display: swap`，并以常见中文衬线字体和系统字体兜底。

## 状态流转

由 `App` 作为唯一协调层维护阶段：`loading` → `settling` → `exiting` → `content`。

- `loading`：模拟进度推进，列车和建筑联动。
- `settling`：进度达到 100% 后先等待建筑队列完成，再停留 350ms 展示完整画面。
- `exiting`：覆盖层在正常模式下用 420ms 退出，主内容同步进入；reduced-motion 下只做 150ms 淡出。
- `content`：从 DOM 移除 Loading，避免它继续拦截交互。

进度 Hook 只产出单调的 0–100 数值。`App` 在进度首次到达 100 时进入 `settling`，等待 `LoadingCity` 报告出现队列清空后才启动 350ms 停留计时，再进入 `exiting`；420ms 退出动画完成后进入 `content`。reduced-motion 对应的停留和退出时长分别为 100ms 与 150ms。不另设可能与进度冲突的 `isComplete`。未来真实资源接入时，资源层只负责提供进度和 `complete | degraded` 结果，阶段仍由 `App` 协调。

Loading 首帧即使用 `position: fixed; inset: 0` 和可靠层级覆盖视口，主内容初始不可见并设置 `inert` 或等效交互隔离。进入 `exiting` 后才开始交叉淡入；覆盖层结束并移除后恢复主内容交互。Loading 不抢占或移动焦点。

开发环境中的 React Strict Mode 可能重复执行副作用；进度计时器必须正确清理，确保不会出现双计时器或卸载后更新状态。

## 异常与降级

- 字体加载失败时使用本地中文衬线字体兜底，不阻塞页面进入。
- 模拟加载不依赖网络请求；任何计时异常都必须触发兜底并在 5 秒内进入内容，不能永久遮挡页面。
- 未来真实资源接口要求 `complete | degraded` 都可进入 `settling`，并设置最大等待时间；异常或超时走降级结果而非永久停留。
- 页面切到后台时，浏览器可能降低计时器频率；恢复后以当前时间重新计算进度，避免大量补帧。
- 动画不可用或用户要求减少动态效果时，页面仍显示清晰的百分比和状态文案。

## 验收标准

- 首次进入时 Loading 覆盖整个视口，不闪现后方内容。
- 列车位置、百分比和加载状态始终一致。
- 建筑按列车经过的顺序逐个出现，而不是同时播放。
- 100% 后完成停留与退场，主页面可正常交互，覆盖层已移除。
- 320px 宽手机到常见桌面视口均无横向滚动、裁切或文字重叠。
- 全站文字及表单控件优先使用方正大标宋简体。
- `prefers-reduced-motion` 下无明显位移、弹跳或持续呼吸。
- TypeScript 构建和 ESLint 检查通过。

## 验证矩阵

- 使用假计时器或可控时钟验证进度单调、3.6 秒完成一次，以及 `loading → 等待建筑队列 → 350ms settling → 420ms exiting → content` 的完整顺序；同时验证 reduced-motion 的 100ms 停留与 150ms 退出。
- 注入跳跃进度验证多个建筑仍按索引以 90ms 间隔出现，且列车与数字不受事件队列影响。
- 在 React Strict Mode 下验证只有一个有效动画循环，卸载后无状态更新。
- 在 320px、600px 和桌面视口浏览器检查主体、百分比与文案无溢出或重叠。
- 强制 `prefers-reduced-motion: reduce`，检查无 transform、弹跳和持续动画。
- 使用无障碍扫描并手工确认 progressbar 名称、限频数值、主内容隔离与焦点不被抢占。
- 运行 TypeScript 构建和 ESLint；在真实浏览器完成一次首屏进入和退场验收。

## 非目标

- 本次不接入真实资源清单、预加载管理器或失败重试界面。
- 不新增路由、全局状态库或第三方动画依赖。
- 不复刻 Figma 中某一整幅场景，只提取其配色、城市轮廓和叙事语言。
