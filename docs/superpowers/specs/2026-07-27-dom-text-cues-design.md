# DOM 文字 Cue 替换设计

## 1. 目标

将长卷叙事中独立导出的 1× 标题、正文、注释和数据来源 PNG 替换为真实 DOM
文字，消除高分屏和放大视口下的插值模糊，同时保持现有 Figma 构图、文案、
滚动节奏和场景层级。

本次替换不重新设计页面，不修改图表内容，不重做 2× 场景素材，也不改变
ScrollTrigger 与 GSAP 主时间线。

## 2. 已确认事实

- 场景背景和前景通常以 1620px 高度导出，对应 810px 逻辑画布，属于 2× 素材。
- 主要叙事文字位于 `public/assets/cues/*.png`，多数按 Figma 逻辑尺寸 1× 导出。
- 这些 1× 文字素材是独立透明 cue，不需要从背景图中修复或抹除。
- 现有 `.chronicle-cue` 容器已经负责逻辑坐标、层级、显隐和滚动动画。
- Figma 文件 `cxUHkI5OuXTwVRbOIuzev5` 中保留了 cue 对应的原始文本节点。
- 已通过 Figma 只读接口确认，可取得准确中文、字号、字体、行高、文本框尺寸和
  对齐方式，不需要使用 OCR。
- 绝大多数文本使用 `FZDaBiaoSong-B06S Regular`；项目已包含相应方正大标宋字体
  文件并声明为 `FZ Da Biao Song`。

## 3. 已批准范围

### 3.1 改为 DOM 的内容

`src/sceneCues.ts` 中所有独立的下列 cue：

- `title`：年代标题；
- `copy`：叙事正文、引用和普通说明；
- `source`：数据来源与注释。

其中，一个 Figma 父节点包含多个分散文本节点时，应按 Figma 文本节点拆成多个
可独立定位的 DOM 文本块，不再通过一张超宽 PNG 的裁剪窗口复用内容。

### 3.2 保持原样的内容

- 2× 场景背景与前景；
- SVG 图表及图表内部文字；
- 黑板报、信件、手写回忆录等作为历史物件组成部分的文字；
- `handwritten-letter.png` 等插画；
- 高分辨率封面标题素材；
- 船、雨、遮罩、人物和其他非文字素材。

如果某段普通数据来源只存在于 2× 场景图中，本轮按“2× 图片不处理”的已确认
边界保留，不对场景图做修补。

### 3.3 资源清理

首轮实现只停止渲染和预加载被替换的 1× 文字 PNG，不删除原文件。完成视觉验收
后，可另行决定是否删除未引用资产。这样可以在不触碰场景原图的情况下保留快速
回退能力。

## 4. 设计方案

### 4.1 单一数据源

继续以 `src/sceneCues.ts` 作为 cue 坐标和内容的唯一机器可读来源，不新增第二份
平行坐标表。

将 `SceneCue` 改为以 `kind` 判别的联合类型，避免文字 cue 继续静默携带图片：

- `TextSceneCue`：`kind` 为 `title / copy / source`，必须包含
  `textBlocks`，并禁止 `asset / svgAsset / crop`；
- `ChartSceneCue`：`kind` 为 `chart`，必须包含现有 SVG 资源；
- `IllustrationSceneCue`：`kind` 为 `illustration`，必须包含图片资源。

`TextBlock` 至少包含：

- 准确字符内容；
- 唯一 Figma 文本节点 ID；
- 相对于所属 cue 外框的 `x / y / width / height`；
- 字号、行高、字距、对齐方式和颜色；
- 显式段落或受控换行；
- 必要时的语义标签或无障碍文本。

图表和插画 cue 继续使用现有资产字段。文字 cue 不再依赖 `asset` 才能成立，避免
用空字符串或透明占位图模拟真实文字。现有通用 `cue()` 工厂应拆成类型安全的
`textCue / chartCue / illustrationCue`，不能继续为所有 kind 自动生成 PNG URL。

### 4.2 多文本节点与动画身份

一个现有 manifest cue 仍对应一个外层 `.chronicle-cue`，保留原 cue ID、逻辑
外框、进入时间和动画身份；其内部可以包含一个或多个 `TextBlock`。

对于 `s02`、`s03`、`s11`、`s13`、`s17` 等原先通过超宽 PNG 和多个 crop 窗口
复用的内容：

1. 保留现有 crop cue 的数量和 ID，避免改变延迟入场时刻；
2. 按 Figma 文本节点的场景绝对坐标，将节点分配给覆盖它的现有 cue；
3. 将节点坐标换算为 cue 外框的相对坐标；
4. DOM 版本不再保留 `crop`，也不渲染整张超宽图片；
5. 一个 cue 内的多个 `TextBlock` 随外层 cue 一起动画；
6. 不允许同一个 Figma 文本节点在同一时刻被两个 cue 重复渲染。

若某个 Figma 文本节点跨越两个既有 crop 外框，实施前必须明确唯一归属，并扩大该
cue 的无裁切 DOM 外框或拆分为具有独立稳定 ID 的新 cue；不得通过重复文本模拟
裁切。

### 4.3 DOM 渲染边界

新增一个专门负责文字的 cue 渲染单元，并由 `SceneContent` 按 cue 类型分派：

- 文字 cue 渲染为真实文本元素；
- 图表继续渲染 SVG；
- 插画继续渲染 `<img>`。

外层 `.chronicle-cue`、`data-cue`、`data-cue-kind`、`data-cue-mode` 和
`data-figma-node` 保持不变。GSAP 继续只操作 cue 外层，因此文字替换不改变入场、
停留、退场、反向滚动和静态预览逻辑。

标题使用标题语义，正文和来源使用段落语义。视觉隐藏与时间线控制仍由现有
`autoAlpha` 和 cue 状态负责，不创建第二套显隐状态机。

`SceneContent` 必须移除当前 `item.kind !== 'source'` 的排除条件。所有 `source`
cue 都渲染在所属 scene 的普通 content surface 中，并使用 manifest 的 scene
逻辑坐标。一个来源父组含有多个 Figma 文本节点时，按与正文相同的
`textBlocks` 规则渲染；来源文字不恢复已删除的底部背景层，也不另建全局 fixed
层。

### 4.4 坐标与排版

所有文字继续位于 810px 高的 Figma 逻辑坐标系中，并随所属 scene 等比缩放：

- 保持 Figma 固定文本框宽度；
- 保持原始段落和手动换行；
- 不根据浏览器宽度重新排版；
- 默认正文按 Figma 使用 `text-align: justify`；
- 年代标题保持 60px 字号、40px 行高等节点原始属性；
- 正文与来源按各节点的 12px/14px/32px 等原始字号和 20px/24px/28px/70px
  等原始行高表达，不用一个全局尺寸覆盖所有场景。

浏览器与 Figma 的字体度量可能造成自动换行差异。实现时优先使用相同字体、
固定框宽和原始段落；若截图对照仍出现行尾漂移，则为该文本块记录受控换行，
而不是修改全局字距或缩放文字。

### 4.5 字体

统一通过项目自带字体渲染 DOM cue。字体声明使用与 Vite `base` 一致的资源路径。
现有 WOFF2 是子集，只有在机器检查证明它覆盖全部 DOM cue 字符后才能作为首选；
否则必须以完整 TTF 为首选，不允许缺失字形静默回退到另一种宋体。也可以生成并
提交覆盖全部 cue 字符的完整 WOFF2，但不能假定现有子集天然完整。

进入内容前继续等待字体加载。预加载逻辑应验证页面实际声明的字体，而不是维护
一个未参与 `@font-face` 的旁路 URL。

字体加载失败时使用现有宋体回退栈，页面必须可读；加载成功后不得发生永久性的
图片文字回退。

### 4.6 预加载

`useAssetPreloader` 不再把已 DOM 化的文字 PNG 计入关键图片任务。关键任务保留：

- 场景背景与前景；
- 图表或插画资产；
- 封面与船素材；
- 实际 DOM 字体。

这样既减少图片请求，也避免为不再显示的 1× cue 阻塞进入动画。

### 4.7 现有用户改动

当前工作树已经包含底部注释背景移除和 Scene 19 图层归属调整等未提交修改。
实现必须在其上增量工作，不恢复 `bottom-annotation.png`，不回滚现有
`ScrollChronicle.tsx` 与 `index.css` 改动。

数据来源改为 DOM 后直接使用 scene 内容层与现有 cue 时间线，不重新引入已删除的
底部注释背景组件。

## 5. 视觉保真

目标是保持构图与动画一致，同时让字体在最终设备分辨率上重新栅格化。以下变化
属于预期：

- 字边缘比旧 1× PNG 更清晰；
- 浏览器抗锯齿与 Figma 导出 PNG 不会逐像素相同；
- 文字可选择、可搜索，并能被辅助技术读取。

以下变化不允许出现：

- 文本框位置或尺寸明显漂移；
- 行数、段落顺序或原始文案变化；
- 文字越过原遮挡、人物或图表边界；
- 文字在滚动时间线中的出现顺序改变；
- 同一位置同时出现 PNG 旧字和 DOM 新字；
- 2× 场景图、图表或历史物件被重绘。

## 6. 错误与降级

- Figma 节点读取失败时，不使用 OCR 猜写；记录缺失节点并停止该 cue 的替换。
- 字体属性存在混合样式时，按 Figma styled segments 保存，不把整段强制为一种
  样式。
- 某 cue 无法在浏览器中稳定复现原换行时，只对该 cue 增加显式换行。
- 任何仍需依赖 PNG 的例外必须在验收记录中列出，不能静默回退。

## 7. 验证

### 7.1 机器检查

- TypeScript 构建通过；
- ESLint 通过；
- 每个 `title / copy / source` cue 都有非空真实文本；
- DOM 化 cue 不再生成 `<img src=".../assets/cues/...">`；
- 被替换的文字 PNG 不再进入关键预加载列表；
- 图表和插画仍保持原资源渲染；
- 现有 cue ID、模式和动画查询选择器保持有效。
- `TextSceneCue` 在类型层禁止图片字段，图表和插画在类型层要求对应资源字段；
- 全部 DOM cue 字符的字体覆盖检查通过；若 WOFF2 不完整，则确认运行时使用完整
  TTF，且不存在逐字回退。

### 7.2 视觉检查

建立 cue 级验收矩阵。矩阵必须列出每个 DOM cue 的 scene、cue ID、Figma 节点
ID、可见静态进度、基准截图和实现后截图。

以下覆盖是强制项：

- `1440 × 810`：每个 DOM cue 均有可见状态对照，不能只抽查 scene；
- `1920 × 1080`：每个 scene 至少一个稳定可见检查点；
- `2560 × 1440`：每个 scene 至少一个稳定可见检查点；
- 所有原 cropped group 和所有 `source` cue 在三档视口均有检查点。

每个检查点等待字体加载完成后截图，检查：

- 文案、段落和换行；
- 文本框坐标与边界；
- 字号、行高、颜色和对齐；
- 与人物、图表、前景遮挡的层级；
- 无 PNG/DOM 重影；
- 清晰度相对旧 1× cue 有可见提升。

### 7.3 动态检查

- 为每个 scene 记录至少一个稳定可见 document progress；
- 在该 progress 分别执行直接静态定位、正向抵达、反向抵达和快速来回后抵达，
  cue 的文字、bounds、opacity 和 transform 必须一致；
- reduced-motion 模式在同一 scene 检查点内容完整；
- 每个延迟入场 cue 在进入前、进入中、稳定可见三个时间点验证顺序不变；
- 静态预览与正常时间线在相同语义进度显示同一内容；
- 字体加载前后不出现永久布局错位。

验收结果保存为可追踪的截图或 contact sheet，并记录 cue 级通过状态。若自动像素
比较受字体抗锯齿差异影响，应以文本框 bounds、行数、换行位置和人工视觉对照共同
判定，不得仅因平均像素差较大而回退到 PNG。

## 8. 完成定义

1. 所有独立 1× `title / copy / source` cue 均由 DOM 渲染。
2. 2× 场景、SVG 图表和历史物件不变。
3. 原 1× 文字图片不再显示或预加载，且没有新旧文字重影。
4. 文案来自 Figma 原节点，无 OCR 猜写或乱码。
5. 现有滚动、反向、静态预览和 reduced-motion 行为保持。
6. 构建、Lint、机器断言和三档视口视觉检查通过，或对未验证项明确记录原因。
