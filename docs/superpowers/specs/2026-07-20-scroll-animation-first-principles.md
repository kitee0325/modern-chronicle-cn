# 滚动叙事动画第一性原理 Spec

## 1. 目标

把 21 组已交付画面组织成一条可正向、可反向、可停在任意位置的连续滚动旅程。页面不是 21 张依次切换的幻灯片，而是一台由用户滚动直接操纵的摄影机：横向穿越历史场景，在列车车窗与窗外世界之间下钻、上浮，并由同一艘小船贯穿始终。

本 Spec 负责定义动画规则、画面坐标、转场、响应式策略、可逆性和验收边界。它不重新设计已有场景，也不修改文案与图表内容。

## 2. 已确认事实

- Figma `交付区` 中有 21 个连续画面节点，可与 `public/assets/scenes/Scene_01` 至 `Scene_21` 按顺序和画布宽度一一对应。
- 所有导出 PNG 高度均为 `1620px`，对应 Figma 的 `810px` 逻辑高度；素材按 2× 分辨率交付。
- 列车外场景是横向连续世界。画布越宽，允许看到越多内容。
- 只有列车车厢拥有明确的前景遮挡；车窗后方必须能看到相邻的窗外世界。
- 用户可以任意向前或向后滚动，不使用整屏吸附，也不自动补完动画。
- 除小船自然摇晃外，所有位移、缩放、渐变、文字和图表动画都必须由滚动进度直接控制。
- 小船在逻辑上始终是同一个全局角色。贴图、大小和层级可以改变，但身份与路径连续性不能重置。
- 列车内的小船属于窗外世界层，必须受到车窗遮罩，不能漂到人物、座椅或车厢文字之上。
- 最终画面中，小船驶出右侧，表达旅程仍在继续。

## 3. 第一性原理

### 3.1 滚动位置就是叙事时间

对除环境循环外的任一视觉属性，都应满足：

```text
visualState = f(scrollProgress, viewportMetrics, authoredSceneData)
```

同一视口条件下，用户从任意方向到达同一滚动位置时，应得到同一叙事画面。不得用进入次数、播放完成标记或定时器决定画面状态。

小船摇晃是唯一允许脱离滚动进度持续运行的环境循环。它只能表达水面浮动，不能承担前进、退后、进出场或换皮等叙事含义。

### 3.2 正向与反向是同一条时间轴

- 正向滚动推进时间轴。
- 反向滚动回退同一时间轴，而不是触发另一套“返回动画”。
- 用户停止滚动时，所有叙事动画必须立即停止在当前状态。
- 使用 GSAP 时，主时间轴采用 `ScrollTrigger` 的 `scrub: true`。禁止数值型 `scrub`，因为数值型 scrub 会在滚动停止后继续追赶进度。
- 不把 `ScrollTrigger` 分散到主时间轴的子 tween 上；一个顶层 ScrollTrigger 控制整条主时间轴。
- 横向摄影机移动使用线性映射 `ease: "none"`。文字、图表和门户内部可以使用可逆缓动，但其播放头仍由滚动直接控制。
- 不使用 `toggleActions`、`setTimeout` 或 IntersectionObserver 回调来补做主叙事动画。

### 3.3 不存在“切页”，只有摄影机和层级变化

全篇维护两条彼此独立的连续横向轨道：`interior`（车内）与
`exterior`（车窗外）。任一滚动区间只聚焦并推进其中一条轨道；另一条轨道保持
摄影机位置不变。车内素材可以在构建上连续排列，但叙事上不要求相邻。

跨轨切换前，允许在目标轨道不可见时直接预定位到目标 scene。尤其从车窗外上浮
回到车内时，车内轨道必须先完成预定位，再进入车窗通道，不能让用户看到车厢素材
之间的拼接过程。车外连续世界的素材接缝属于可接受的画面事实，只要不露透明空白。

画面之间只允许四类基础转场：

1. **横向穿越**：摄影机沿连续世界移动，前一画面自然离开、后一画面自然进入。
2. **下钻车窗**：从车厢内部穿过车窗进入窗外世界。
3. **上浮车窗**：从窗外世界反向缩回车窗，回到车厢内部。
4. **同构渐变**：几何构图保持不动，只改变色调、光照、纹理或内容显隐。

不得用整屏硬切或无理由的全屏淡入淡出替代可建立空间关系的转场。只有在两张素材边缘无法无缝衔接时，才允许在遮挡物后使用很短的蒙版溶解隐藏接缝。

## 4. 舞台与坐标系统

### 4.1 逻辑舞台

- 设计安全舞台：`1440 × 810`，比例 `16:9`。
- 交付素材按 2× 渲染，显示时以 `0.5` 为基础换算到逻辑坐标。
- 页面滚动发生在纵向文档；叙事舞台在有效区间内保持 pinned，内部摄影机做横向移动和门户缩放。
- 所有场景、车窗锚点、文本锚点、小船路径点都使用同一套 1440×810 逻辑坐标，禁止直接用当前设备像素写路径。

### 4.2 窄屏

窄屏不重新排版 21 个场景，而是保持电影画幅：

- 完整 16:9 安全舞台等比缩放到视口宽度。
- 剩余垂直空间使用纯黑上下遮幅。
- 不拉伸、不压扁、不为了填满竖屏而裁掉关键人物、图表或车窗。
- 页面仍使用纵向原生滚动；黑边不承载按钮、图表或正文。

### 4.3 宽屏外景

- 以舞台高度为基准等比缩放。
- 视口越宽，摄影机逻辑可视宽度越大；优先展示全景素材中更多的左右内容，而不是放大中央 16:9 区域。
- 摄影机位置必须 clamp 在素材有效边界内，不得露出透明空白。
- 小船路径、文字锚点和图表触发以逻辑世界坐标计算，不因宽屏多看到内容而改变叙事顺序。

### 4.4 宽屏列车内

- 1440×810 是不可破坏的核心构图，人物、车窗与文字保持原比例和相对关系。
- 若车厢全景在左右方向存在已绘制内容，可以在宽屏上自然多展示这些内容。
- 超出车厢有效素材边界后，用深色车厢边缘、既有纹理延展或黑色侧遮幅补足；不得水平拉伸车厢，也不得凭空复制人物或窗户。
- 车窗通道锚点始终定义在核心 16:9 安全区内，避免同一转场在不同比例下指向不同窗口。
- 从宽屏外景进入车厢时，额外可视区域在门户后半段收束到车厢安全构图；从车厢下钻时做相反变化。该变化必须属于滚动时间轴，不得在媒体查询切换时瞬间跳变。

## 5. 场景分层

每个滚动画面按需要使用以下层级。没有对应素材的层可以省略，但顺序不能混乱：

1. `stage-matte`：黑色电影遮幅与舞台底色。
2. `exterior-background`：天空、水面、远山、城市等窗外后景。
3. `boat-route`：由滚动控制的全局小船路径容器。
4. `boat-bob`：小船路径容器内唯一持续循环的摇晃节点。
5. `exterior-foreground`：岸线、树木、建筑、遮挡物。
6. `carriage-foreground`：列车结构、人物、座椅和车窗框。
7. `content-overlay`：文案、图表、数据来源和注释。
8. `texture-overlay`：纸张、颗粒、统一视觉肌理。

列车内画面必须先渲染窗外世界，再用车厢前景覆盖。车窗是窗外世界的可视遮罩，而不是一张不透明的白色占位图。

## 6. 全局小船

### 6.1 单一身份

全篇只创建一个逻辑小船演员。每个滚动画面只声明它在该区间内的状态：

- 路径起点和终点；
- 水线高度；
- 显示比例；
- 贴图或皮肤；
- 所属遮罩；
- 与前后景的遮挡层级。

禁止在每个画面各自创建一艘船后用显隐假装连续。

### 6.2 路径与摇晃分离

必须使用嵌套变换，避免两个动画争夺同一个 `transform`：

```text
boat-route    ← x / y / scale / skin，由 scroll progress 控制
└─ boat-bob   ← 低幅度 rotation / y，独立无限循环
   └─ sprite
```

建议摇晃保持克制：约 `±1°–2°` 旋转与极小的垂直起伏，使用平滑 yoyo 循环。它在滚动停止时继续，在正向和反向滚动时都不重启。

### 6.3 反向滚动

反向滚动只是倒放航行路径。小船贴图朝向不根据瞬时滚动方向翻转，以保证同一滚动位置的构图稳定，并避免触控板微小方向抖动导致船体左右闪烁。

### 6.4 换皮

换皮发生在明确的滚动区间内：旧贴图和新贴图短距离交叉淡化，并同时插值尺寸和锚点。禁止在单个进度点直接替换 `src` 产生闪烁。

### 6.5 车厢内部

小船仍位于窗外世界层：

- 只通过有效车窗可见；
- 可依次穿过多个车窗，但不能覆盖窗框；
- 在下钻过程中由窗口内的小船自然过渡为全屏外景中的小船；
- 在上浮过程中执行完全相反的过程。

## 7. 通用车窗通道

### 7.1 数据要求

每次下钻或上浮都必须声明：

- `windowRect`：目标车窗在 1440×810 安全舞台中的矩形；
- `exteriorScene`：车窗后方预先渲染的窗外世界；
- `exteriorCamera`：窗口初始看到的窗外世界位置；
- `portalWeight`：该转场占用的滚动权重；
- `occluders`：窗框、人物或其他必须保持在最上方的遮挡层。

### 7.2 下钻

下钻不是简单放大整张车厢图，而是把车窗当作摄影机门户：

1. **对准**：车厢仍占满舞台，下一外景已经渲染在车窗后方；小船在窗口内连续运动。
2. **穿窗**：围绕目标窗口中心平移并缩放车厢前景，窗口从局部区域扩大到覆盖安全舞台。
3. **交接**：窗框移出画面，外景从窗口裁切状态变为完整摄影机视口。
4. **稳定**：外景摄影机接管横向穿越，小船不重置位置或摇晃相位。

### 7.3 上浮

上浮严格使用下钻的逆过程：

1. 外景摄影机向目标位置收束；
2. 目标车厢前景从舞台边缘进入；
3. 外景逐渐被约束到目标车窗；
4. 车厢恢复核心 16:9 构图，小船继续在窗外世界层航行。

同一门户实现必须可以通过进度 `p` 与 `1-p` 表达两个方向，不能维护两套几何关键帧。

## 8. 横向穿越与同构渐变

### 8.1 横向穿越

- 把相邻外景布置在同一个横向世界轨道中，移动摄影机而不是逐张移动“页面”。
- 摄影机横向位置与滚动进度线性对应。
- 有共同树木、柱子、窗框等遮挡时，优先把接缝放在遮挡物后。
- 无法直接拼接时，允许在接缝附近使用窄蒙版溶解；溶解只负责藏接缝，不能取代横向位移。
- 宽屏只改变同一摄影机能看到的范围，不改变接缝通过舞台中心的叙事时刻。

### 8.2 同构渐变

`Scene_08 → Scene_09` 使用同构渐变：

- 锁定山体、水面、船和主要构图的位置；
- 交叉插值天空、色调、纹理和必要内容；
- 不在渐变期间额外缩放摄影机；
- 反向滚动时完全恢复原始配色与内容。

## 9. 文本和图表动画

### 9.1 统一生命周期

Cover 标题是唯一例外：它在内容页面首次可见时以 DOM 文字执行一次约 820ms 的
非滚动入场，不改变最终位置，也不参与反向滚动。Cover 横移、前言滚动、短暂停顿
以及到 Scene 01 的缩放混合均属于主 scroll timeline；Scene 01 的年代标题与正文
也遵循下述统一生命周期。

每个内容块都在所属滚动画面内声明四段局部进度：

```text
concealed → entering → held → leaving
```

- `concealed`：明确的初始状态，例如透明、轻微下移或被裁切。
- `entering`：随滚动进入，不自行播放。
- `held`：保持清晰可读，摄影机可以继续缓慢移动。
- `leaving`：在被遮挡、移出安全区或进入下一内容前退出。

反向滚动自然经过 `leaving → held → entering → concealed`。不需要记录“是否已经播放过”，也不需要监听元素是否进入视口后重新启动动画。

默认情况下，`entering` 与主要 `held` 阅读节拍内摄影机完全静止；只有具体 scene
明确要求时，才允许在 `held` 后段进行缓慢运镜。内容节拍结束后，主摄影机再继续
横向移动或进入车窗转场。

### 9.2 文本

- 默认使用 `opacity + y + clip` 的克制组合；位移距离应小，避免字幕像独立卡片飞入。
- 同一段落按段落整体进入；只有设计明确要求时才逐行或逐字。
- 文本必须有足够的 held 区间，不能一出现就离开。
- 文本离开安全舞台后处于确定的隐藏状态，但该状态仍由时间轴进度决定。

### 9.3 图表

- 坐标轴、基线或容器先出现，数据标记随后出现，注释和来源最后出现。
- 柱、线、点、气泡等从有语义的基准值生长；不得用无意义的整图缩放代替数据动画。
- 图表内部 stagger 使用主时间轴中的相对权重，不使用毫秒定时器。
- 反向滚动时数据按相反顺序收回。

## 10. 滚动距离分配

21 个滚动画面不平均分配滚动距离。每段距离由三部分组成：

1. 摄影机需要移动的逻辑距离；
2. 文本与图表需要保持可读的节拍数量；
3. 门户或渐变转场需要的操作空间。

建议以“一个 1440×810 视口的纵向滚动距离”为一个基础权重：

- 横向全景：按实际摄影机旅行距离换算，最少 1 个权重；
- 下钻或上浮：约 `0.8–1.2` 个权重；
- 同构渐变：约 `0.5–0.8` 个权重；
- 一个需要阅读的文本或图表节拍：额外 `0.35–0.6` 个权重，可与较慢的横移重叠。

最终以可读性和运镜速度验收，不以每段 CSS 高度相等为目标。页面不设置 snap 点。

| `Scene_21` | `Scene_09_01（待定）` | 最终外景/长卷 | 驶出 | 摄影机完成长卷横移；总结内容进入并保持后，小船继续向右驶出画面。 |

上表定义的是画面之间的空间关系。每个宽幅画面内部仍可包含多段横移、文本和图表节拍，但不能改变其离场转场类型。

## 12. 建议的数据契约

实现时由一份声明式配置描述画面，避免在组件中散落坐标和条件分支：

```ts
type ScrollShot = {
  id: number
  asset: {
    background?: string
    foreground?: string
  }
  worldSize: { width: number; height: 810 }
  presentation: 'interior' | 'exterior' | 'hybrid'
  track: 'interior' | 'exterior'
  camera: CameraKeyframe[]
  boat: BoatKeyframe[]
  content: ContentCue[]
  transitionOut: HorizontalTransition | WindowPortal | GradientTransition | JourneyExit
  timing: {
    contentRevealRatio: number
    contentHoldRatio: number
    cameraRatio: number
    transitionRatio: number
  }
  scrollWeight: number
}
```

配置只声明事实和关键帧；统一的动画引擎负责：

- 把权重转换成主时间轴区间；
- 构建正反向共用的 GSAP timeline；
- 维护唯一小船演员；
- 应用窗口遮罩和响应式摄影机；
- 在 viewport resize 后重新测量并 refresh。

## 13. 性能与资源约束

现有全景最长达到约 `15734×1620`，不能假设所有设备都适合把整张超长 PNG 作为一个长期驻留的 GPU 图层。

- 超长全景应在构建期切成有重叠边缘的横向瓦片；建议单片宽度不超过 `4096px`，接缝落在低细节或遮挡区域。
- 只解码当前画面、前一画面和后一画面的素材；更远画面可以预取 URL，但不必全部同时提升为活动合成层。
- 图片 decode 和字体就绪后再首次 `ScrollTrigger.refresh()`，避免测量变化造成跳动。
- 位移、缩放和旋转使用 transform；显隐使用 opacity。避免动画修改 `left`、`top`、`width` 和 `height`。
- `will-change` 只用于当前参与动画的摄影机、门户和小船节点，不对全部图层常驻开启。
- resize、设备旋转或断点切换时，保存当前语义进度，重建尺寸相关关键帧后恢复到同一进度。
- React 卸载或重建场景时必须 revert GSAP context，并清理 ScrollTrigger 和环境循环。

## 14. Reduced Motion

`prefers-reduced-motion: reduce` 是正常规则的无障碍覆盖：

- 停止小船持续摇晃；
- 禁用大幅窗口缩放、视差和长距离运动；
- 保留原生自由滚动，以短距离淡化或静态构图连接内容；
- 文本和图表直接进入可读状态，不逐字、逐项生长；
- 不改变内容顺序，也不隐藏任何叙事信息。

## 15. 验收标准

### 15.1 可逆性

- 从任意位置前滚、后滚再回到原位置，除小船摇晃相位外，截图应一致。
- 快速跨越多个画面后立即反向，不出现未完成的独立 tween、排队动画或错误显隐。
- 滚动停止后，只有小船摇晃仍在变化。

### 15.2 小船连续性

- 全篇 DOM 或渲染模型中只有一个逻辑小船演员。
- 小船经过 20 个画面边界时不瞬移、不闪烁、不重置摇晃。
- 列车内的小船只在车窗内可见，并正确受到窗框和人物遮挡。
- 最终小船从右侧完整驶出，而不是原地淡出。

### 15.3 转场

- 20 个 scene 间转场与矩阵一致。
- 下钻和对应的反向上浮使用同一套门户几何。
- `Scene_08 → Scene_09` 构图不漂移，只发生同构渐变。
- 横向接缝在正常速度和快速滚动下均不露透明空白。

### 15.4 内容动画

- 每个文本和图表都有明确的 concealed、entering、held、leaving 区间。
- 正向和反向顺序成立，且不依赖“播放过”状态。
- 文本 held 区间足够阅读，图表数据动画保留数据语义。

### 15.5 响应式

至少验证：

- `360×800`：16:9 画面完整显示，上下黑边，无横向页面滚动；
- `1440×810`：与 Figma 安全舞台一致；
- `2560×1080`：外景展示更多左右内容，车厢不拉伸；
- `3440×1440`：外景无空白，车厢有效边界外使用可接受的侧向延展或遮幅；
- resize 前后保持同一语义进度，不突然跳到相邻画面。

### 15.6 交互与无障碍

- 使用浏览器原生纵向滚动，不劫持 wheel/touch，不设置 scene snap。
- 键盘、滚动条拖动、触控板和触摸滚动都能双向控制同一时间轴。
- `prefers-reduced-motion` 下没有持续摇晃、大幅缩放或强视差，全部内容仍可阅读。

## 16. 非目标

- 不在本 Spec 中重画 21 组场景素材。
- 不重新组织历史叙事、文案或图表数据。
- 不加入自动播放、自动翻页、滚轮劫持或强制吸附。
- 不为窄屏重新设计竖版场景。
- 不在当前阶段定义音频、旁白或声音与滚动的同步方式。
